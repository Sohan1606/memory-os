# MEMORY//OS V8.4.2 — Advanced Explanation Engine

V8.4.2 implements an auditable explanation engine that answers WHY the system reached any cognitive result from observable evidence, without synthetic chain-of-thought or fabricated reasoning.

```text
CONVERSATION / OBJECT FOCUS / RETRIEVAL / DECISION / WORLD CHANGE
             ↓
    EXPLANATION ENGINE
             ↓
[Auditable Explanation Graph Model]
  ├── Explanation Class (20+ Classes)
  ├── Query Intent (Why, Why Not, Why Now, What Changed, Evidence, Alternatives, Causality)
  ├── Decisive Factors (Weighted factor scores & status)
  ├── Alternative Analysis (Competing candidates & rejection reasons)
  ├── Evidence Drill-Down (Supporting & counterexample observations)
  ├── Causal Graph (Upstream causes & downstream effects)
  ├── Historical Truth vs Current State (Preserved then vs now for corrections)
  └── Canonical Event Timeline & Provenance
```

## Architectural decisions

V8.4.2 extends the existing cognitive subsystems:

| Concern | Existing subsystem reused | V8.4.2 extension |
|---|---|---|
| Explanations | `Cognition` event/arbitration inspection | `ExplanationEngine` (`backend/app/cognition/explanation.py`) creates structured, auditable explanation graphs |
| Explanation Classes | V8-V8.4.1 domain events & records | Support for 20+ first-class explanation classes across all subsystems |
| Query Intents | Single why text summaries | 7 distinct query paths: `why`, `why_not`, `why_now`, `what_changed`, `what_evidence`, `what_alternatives`, `what_caused_change` |
| Alternatives Analysis | `ArbiterV2` candidate factors | Preserves and compares candidates with explicit rejection reasons (lifecycle, score, preconditions, scope) |
| Corrections & History | `KnowledgeService` / `MemoryService` transitions | Preserves historical truth while highlighting current state and specific correction events |
| Snapshots | Additive SQLite schema | `SCHEMA_V842` (`explanation_snapshots` table) persists full auditable graphs |
| Conversational Tools | Cognitive tools | `explain_cognition` tool connects directly to `ExplanationEngine` with focus resolution |
| Observatory UI | `WhyInspector` | Comprehensive explanation inspector with interactive intent tabs and evidence drill-down |

## Conversational Tool (`explain_cognition`)

- **Name**: `explain_cognition` (with backward-compatible alias `explain`)
- **Intents**: `why`, `why_not`, `why_now`, `what_changed`, `what_evidence`, `what_alternatives`, `what_caused_change`
- **Focus Resolution**: Automatically resolves focused Skill, Principle, Memory, Mission, or Decision when `subject_id` is omitted.
- **Structured State Contract**: Returns canonical structured objects `state_now = {"lifecycle": "...", "eligible_for_retrieval": bool, "scope": ...}` and `state_then = {"lifecycle": "...", ...}` without flattening to strings.
- **Guidance & Disambiguation**: System prompt explicitly distinguishes `inspect_learned` (reading static state) from `explain_cognition` (explaining why/why not/what changed via event, arbitration, decision, and causal records).

## Explanation Classes

1. `MEMORY_RECALL` — Why a memory was retrieved (confidence, active lifecycle, query match, recency)
2. `LEARNED_KNOWLEDGE_RETRIEVAL` — Why a skill/principle was retrieved (trigger match, preconditions, scope, live lifecycle)
3. `ARBITRATION` — Why candidate A won over candidate B with candidate factors and rejection reasons
4. `DECISION_INFLUENCE` — Upstream knowledge/memories that influenced a decision and resulting outcomes
5. `TOOL_SELECTION` — Execution mode and capability routing decisions
6. `INTERVENTION` — Why an intervention was proposed (expected value vs interruption cost)
7. `ATTENTION` — Why an item was suppressed or attended to according to learned silence policy
8. `PREDICTION` — Why a prediction was made with supporting observations and horizon
9. `PREDICTION_OUTCOME` — Why a prediction was evaluated as correct/incorrect with error and surprise metrics
10. `LEARNING` — Why an experience was formed from observed episodes
11. `KNOWLEDGE_VALIDATION` — Why a skill/principle passed or failed validation
12. `KNOWLEDGE_CORRECTION` — Why and how a skill or principle was corrected by user instruction
13. `KNOWLEDGE_RETIREMENT` — Why a learned object was retired and excluded from future retrieval
14. `CAUSAL_CHANGE` — Upstream causes and downstream effects for any cognitive node
15. `CONTINUITY_CHANGE` — Why an open thread/item was resumed or closed
16. `WORLD_CHANGE` — Why a world entity was created, updated, superseded, or flagged stale
17. `INTENT_CHANGE` — Why the inferred objective transitioned to a new state
18. `AUTONOMY_ACTION` — Why an action was permitted under the user's autonomy level and capability trust
19. `AUTONOMY_REFUSAL` — Why an autonomous action was denied or required confirmation
20. `WHY_NOW` — Recent temporal and contextual triggers that made an action relevant at this moment
21. `EXPERIENCE_FORMATION` — Episode enrichment and observation linking
22. `POLICY_CHANGE` — Why a behavioural policy was updated from user utterances
23. `MISSION_STATE_CHANGE` — State changes and blockers on active missions

## API Endpoints

- `GET /api/explanations` — List persisted explanation snapshots
- `GET /api/explanations/{id}` — Retrieve an auditable explanation snapshot
- `GET /api/explanations/subject/{subject_kind}/{subject_id}` — Generate/retrieve explanation graph for a subject
- `GET /api/explanations/decision/{decision_id}` — Explain decision influence and alternatives
- `GET /api/explanations/event/{event_id}` — Explain context behind a canonical event
- `POST /api/explanations/query` — Ad-hoc explanation query with specific intent, depth, and subject
