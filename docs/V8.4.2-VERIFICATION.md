## 1. Explanation Engine Architecture

V8.4.2 introduces the canonical `ExplanationEngine` (`backend/app/cognition/explanation.py`) which builds auditable explanation graphs directly from recorded events, arbitration records, decision histories, and causal linkages.

### Core Capabilities Verified:
1. **20+ Explanation Classes**: Full coverage of `MEMORY_RECALL`, `LEARNED_KNOWLEDGE_RETRIEVAL`, `ARBITRATION`, `DECISION_INFLUENCE`, `TOOL_SELECTION`, `INTERVENTION`, `ATTENTION`, `PREDICTION`, `PREDICTION_OUTCOME`, `LEARNING`, `KNOWLEDGE_VALIDATION`, `KNOWLEDGE_CORRECTION`, `KNOWLEDGE_RETIREMENT`, `CAUSAL_CHANGE`, `CONTINUITY_CHANGE`, `WORLD_CHANGE`, `INTENT_CHANGE`, `AUTONOMY_ACTION`, `AUTONOMY_REFUSAL`, `WHY_NOW`, `EXPERIENCE_FORMATION`, `POLICY_CHANGE`, `MISSION_STATE_CHANGE`.
2. **7 Query Intents**: Deterministic routing for `why`, `why_not`, `why_now`, `what_changed`, `what_evidence`, `what_alternatives`, `what_caused_change`.
3. **Structured State Contract**: `state_now` and `state_then` return rich dictionaries (e.g. `{"lifecycle": "retired", "eligible_for_retrieval": false, "scope": "..."}`) rather than flattened strings.
4. **Historical Truth vs Current State**: Preserves prior verified states alongside user corrections and explicit retirement reasons.
5. **Causal Linkage**: Bidirectional upstream causes and downstream effects traversal.
6. **Namespace Isolation**: Explanations and persisted snapshots are strictly isolated per `user_id`.

## 2. Tool Architecture & Backward Compatibility

### Two Public Explanation Tools Supported:
1. **`explain_cognition` (V8.4.2 Canonical Tool)**:
   - Structured JSON envelope with `explanation_id`, `explanation_type`, `query_intent`, `subject`, `summary`, `decisive_factors`, `supporting_evidence`, `counter_evidence`, `alternatives`, `causality`, `correction`, `state_now`, `state_then`, `epistemic_status: "OBSERVED"`.
2. **`explain` (V8.3.1 Legacy Compatible Adapter)**:
   - For `question_kind="why"`: adapts `ExplanationEngine` results into `{"status": "OK", "subjects": [{"kind": "mission", "id": "...", "label": "...", "mission": ..., "history": ..., "verdict": ...}], "note": ..., "epistemic_status": "OBSERVED"}`.
   - For `question_kind="what_changed"`: returns `{"status": "OK", "world_changes": [...], "mission_history": [{"change": "...", "from": "...", "to": "...", "reason": "...", "when": "..."}], "epistemic_status": "OBSERVED"}`.
