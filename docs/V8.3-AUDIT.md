# V8.3 pre-work audit — what V8.2 actually contains

Produced by reading the code, not the docs. Where the docs and the code
disagreed, the code was treated as authoritative. Two such disagreements were
found and are listed at the bottom.

Baseline: commit `276b525`, `feature/v8.2-cognitive-core`.

## Findings where code contradicts documentation

**Finding 1 — `mission.*` events exist but missions do not.**
`cognition/events.py` declares and labels five mission event types
(`mission.created|updated|progressed|completed|abandoned`), and they are
registered in `EVENT_TYPES`. A repository-wide search for `mission` outside
`events.py` returns **zero** hits in `app/`. There is no mission table, no
mission module, no mission route. The event vocabulary was reserved and never
implemented. V8.3 must implement the entity behind these events rather than
assume it exists.

**Finding 2 — the `world_changes` table has no writer.**
`persistence/db.py` creates `world_changes` with columns for
`previous_state`, `new_state`, `source`, `confidence`, `evidence` and
`correlation_id`, plus an index. No code in `app/` ever inserts into it.
`WorldModel.upsert()` and `set_state()` emit bus events but silently overwrite
state with no recorded history and no reason-for-change. This is the single
biggest gap for a "continuous" world model: today the world has a present but
no past.

## Consequences for V8.3 scope

The genuinely missing systems are: **missions**, **observations**, **background
cognition**, **the time machine**, **world change history + staleness +
reconciliation**, **connector interfaces** and **research scaffolding**.

Everything else is extension, not construction. In particular `arbitration.py`,
`influence.py`, `policy_engine.py`, `trust_v2.py`, `continuity.py` and
`context_builder.py` are working systems that V8.3 should call into — not
reimplement.
