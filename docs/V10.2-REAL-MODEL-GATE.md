# V10.2 REAL-MODEL GATE

This gate is acceptance evidence for the real-provider portion of the V10.2
loop. It is intentionally separate from the deterministic V10.2 CORE and
RUNTIME suites. A deterministic result is **never** real-model evidence.

## Configuration and command

Default model: `llama3.2:3b`.

Environment variables:

- `OLLAMA_BASE_URL` — Ollama HTTP origin (default `http://127.0.0.1:11434`)
- `V102_TEST_MODEL` — installed model name (default `llama3.2:3b`)
- `V102_LLM_TIMEOUT_S` — timeout for each model request (default `180` seconds)

Run from `backend/`:

```bash
pytest tests/test_v102_real_model.py -ra -s
```

The real gate has both `slow` and `v102_real_model` marks. The deterministic
V10.2 files have the `v102_deterministic` mark and are reported separately:

```bash
pytest -m v102_deterministic -ra
pytest -m v102_real_model -ra -s
```

## Truthful result meanings

### CONNECTED / VERIFIED

This may be reported only when the dedicated test executes successfully. It
means the configured Ollama server responded, the requested installed model
was selected through `Runtime(model_provider="ollama",
provider_autodetect=False)`, and an actual cognitive compilation and agent
model call completed without demo or deterministic fallback.

The test also verifies that:

- provider and dependency reporting identify an active Ollama real agent;
- `DEMO_PLANNER`, provider degradation, and deterministic semantic fallback
  are hard failures;
- real model activity is visible in the production execution trace;
- the model-backed cognitive turn reaches the existing bounded
  `PolicyRuntimeCoordinator` under the same correlation id;
- `PolicyEvidenceAssembler`, `LearningSignalDeriver`,
  `PolicyGovernanceService`, `PolicyRuntimeCoordinator`,
  `CognitivePolicyEngine`, and `AutonomyGovernor` are the composition-root
  instances, not test replacements or a second policy engine;
- governance remains deterministic, and model-produced semantic state cannot
  write effective policy or become class-B evidence outside the assembler's
  canonical allowlist; and
- the harmless turn creates no proposal or policy mutation merely because a
  model produced output.

### NOT CONNECTED / NOT VERIFIED

If the Ollama connector/server cannot be reached, its model list is invalid,
or the requested model is not installed, only this slow real-model test is
skipped with an explicit `NOT CONNECTED / NOT VERIFIED` reason. That outcome
blocks only this real-model gate. It does not fail or relabel deterministic
CORE/RUNTIME verification.

A configured provider name, a successful deterministic fallback, or a model
being present in configuration is not verification.

## Legitimately deferred boundary

The gate does **not** manufacture an ACTIVE adaptation. A fresh ATTENTION
adaptation requires at least three independent episodes across at least two
days. No unsafe clock endpoint, direct database backdating, fake provider,
monkeypatch, or evidence-threshold bypass is used in this real-model gate.

Accordingly, creation/confirmation of a fresh ACTIVE adaptation and a later
real-model turn consuming that new adapted value remain **DEFERRED / NOT
VERIFIED by this gate**. Their deterministic architecture and real consumer
seam remain covered by `test_v102_governance_core.py` and
`test_v102_governance_runtime.py`; those results must still be reported as
deterministic evidence only.
