# V8 → V8.1 — Real intelligence

V8.1 keeps every V8 subsystem and changes one thing that matters: the default
experience is no longer a deterministic demo when a local model is available.

## What is new

### 1. Real local agent (Ollama)
A genuine multi-step tool-calling loop. The model decides whether memory is
needed, which tool to call and when it is done. There is no keyword routing
anywhere in the real path.

Verified activity from a real turn:

```
LOAD_CONTEXT → MEMORY_PRELOAD → MODEL_CALL → TOOL_DECISION:search_memory
             → MODEL_CALL → MEMORY_MANAGER
```

See `docs/LOCAL_LLM.md` for setup and `backend/tests/test_v81_real_agent.py`
for the executable proof.

### 2. Provider abstraction with an honest mode
`GET /api/provider` reports provider, model, tool-calling support and a coarse
`mode`:

* `REAL AGENT` — a real LLM is answering.
* `DETERMINISTIC FALLBACK` — no model; the planner answers.

Auto-detection enables real mode without configuration when Ollama is running
and the model is pulled. A configured-but-missing model degrades to the demo
path with an actionable message (`ollama pull ...`) rather than crashing.

### 3. Model-assisted extraction (additive, never destructive)
Intent, need, world entities and memory candidates are extracted by the model
against a strict schema, then validated:

* unknown entity kinds and need types are dropped;
* confidence and importance are clamped to `0..1`;
* memory candidates with no lexical overlap with what the user actually said
  are discarded as hallucinations;
* markdown fences and surrounding prose are stripped before parsing.

The deterministic engine **always** runs first. Model output is merged on top,
so understanding can only improve, never regress below the V8 baseline. Turns
are labelled `deterministic` or `model-assisted`.

> Small models are inconsistent. Measured on `qwen2.5:0.5b`, a usable extraction
> was produced in 3 of 5 runs on the same input. This is exactly why the union
> design exists, and why a larger model is recommended when RAM allows.

### 4. Multimodal perception
Text, voice, image and document converge into one `Perception` record that
flows through the normal pipeline - not four parallel ones.

| Modality | State | Behaviour |
|---|---|---|
| text | ACTIVE | Read in full. |
| document | ACTIVE | Plain text read in full. PDF/Office are NOT CONFIGURED. |
| image | METADATA ONLY | Format and real pixel dimensions parsed from the header. Content is **NOT AVAILABLE** - no vision model is bundled and none is faked. |
| voice | ACTIVE / DEGRADED | Server transcription when configured, browser fallback otherwise. |
| video | NOT CONFIGURED | Not implemented. |

### 5. Memory health engine
Evidence-based diagnosis with **non-destructive** remedies:

| Finding | Remedy | Effect |
|---|---|---|
| duplicate | MERGE | Duplicate soft-retired, original kept. |
| stale / contradicted | REVALIDATE | Flagged for confirmation; nothing changed. |
| low value / unsupported | DOWNGRADE | Importance lowered; memory stays active. |
| harmful | QUARANTINE | Excluded from retrieval; reversible. |
| repeatedly unhelpful | RETIRE | Soft status change; version history preserved. |

Nothing is ever hard-deleted, and nothing is applied automatically. Duplicate
detection compares content words with filler removed and plurals normalised, so
"every Friday" and "each Friday" match while "deploys on Friday" and "never
deploys on Friday" do not. Applying remedies converges: a second diagnosis pass
returns no findings.

## New endpoints

| Method | Path | Purpose |
|---|---|---|
| GET | `/api/provider` | Active provider, model, mode, extraction and perception capabilities. |
| GET | `/api/memory-health` | Diagnosis with grade, findings and cited evidence. |
| POST | `/api/memory-health/apply` | Apply one remedy. Validates against the remedy vocabulary. |
| POST | `/api/perceive` | Ingest a file as one cognitive perception. |

## New event types
`extraction.*`, `perception.*`, `maintenance.*`, `memory.quarantined`,
`memory.merged`, `memory.stale`, `mission.*`, `experiment.*` — 87 total, every
one with a human-readable label. The bus still rejects unknown types.

## Known limits
* Local models below ~1.5B extract inconsistently; tool calling is reliable.
* Image content is never interpreted without a vision model.
* PDF and Office parsing are NOT CONFIGURED.
* LangMem is NOT INSTALLED; extraction is the schema-validated model path above.
* Calendar, email and file connectors remain NOT CONNECTED.
* ROI, time saved and cost avoided always report INSUFFICIENT EVIDENCE.
