# MEMORY//OS V8.3 — Continuous Cognition

V8.3 turns MEMORY//OS from a system that *processes a message* into one that
*maintains a cognitive environment between messages*. Nothing from V8/V8.1/V8.2
was rebuilt or replaced: every system here extends something that already
worked.

The guiding constraint is unchanged and, if anything, tighter than before:
**the system may never claim more than it actually observed.** Most of the code
below exists to make honest answers structurally possible — `NOT CONNECTED`,
`UNRESOLVED`, `HISTORY NOT AVAILABLE`, `INSUFFICIENT EVIDENCE`,
`METADATA ONLY` are first-class outcomes, not error paths.

---

## What the audit found first

V8.3 began with a full read of the V8.2 code (see `docs/V8.3-AUDIT.md`). Two
places where the code contradicted the documentation shaped the whole release:

1. **`mission.*` events existed; missions did not.** Five mission event types
   were declared and labelled in `events.py`, registered in `EVENT_TYPES`, and
   emitted by nothing. There was no mission table, module or route. V8.3
   implements the entity those events were reserved for.

2. **`world_changes` had no writer.** The table, its columns and its index were
   all created; no code ever inserted a row. The world model had a present but
   no past. This is now the backbone of both change provenance and the time
   machine.

## The canonical loop (§2)

```
INPUT → PERCEPTION → UNDERSTANDING → INTENT → NEED → CONTEXT → MEMORY
      → WORLD STATE → PREDICTION → ATTENTION → INTERVENTION DECISION
      → AUTONOMY → ACTION / ASK / WAIT / IGNORE → OBSERVATION → OUTCOME
      → CONSEQUENCE → SURPRISE → LEARNING → MEMORY / WORLD / POLICY EVOLUTION
      → CONTINUITY
```

Stages activate **by relevance**. A short factual reply does not run mission
replanning, staleness sweeps or counterfactual projection. This is a deliberate
performance property: more internal intelligence must never mean a slower or
more expensive turn.

## New subsystems

### Observations (§17) — `cognition/observation.py`

The abstraction V8.2 lacked. An observation is **evidence**, explicitly not a
memory:

- five epistemic states: `OBSERVED` / `INFERRED` / `PREDICTED` / `SIMULATED` /
  `UNKNOWN`, never silently upgraded
- every record carries a traceable `origin` — a message id, filename, or
  prediction id. An observation with no origin is rejected.
- **promotion to memory is always explicit**, and only `OBSERVED` evidence
  qualifies. Promoting an inference would launder a guess into a fact.
- discarding annotates; it never deletes.

### Missions (§10–§12) — `cognition/missions.py`

Objectives that outlive a conversation.

- lifecycle `draft → active → waiting / blocked / paused → completed / failed /
  abandoned`
- **bounded planning**: at most 7 open steps; replanning requires one of six
  recognised triggers, so a mission never spontaneously rewrites its own plan
- **progress is derived, never estimated** — it is the fraction of known steps
  completed. A mission with no steps keeps 0.0 rather than inventing a number.
- every transition writes a `mission_events` row with its reason and evidence
- missions that go quiet for 21 days are **surfaced for review, never
  auto-abandoned**

### World state V2 (§7–§9) — `cognition/world_v2.py`

Wraps `WorldModel`; does not replace it.

- **change provenance**: every mutation appends to `world_changes` with the
  previous value, new value, source, confidence and evidence
- **per-fact-class staleness**: a risk is expected to be re-checked every 14
  days, a person every 180. Crossing the horizon marks a fact `STALE` —
  **stale is not false.** The value is preserved and the caveat is explicit.
- **reconciliation** with six verdicts — `keep`, `supersede`, `merge`, `flag`,
  `downgrade`, `ignore`. Evenly-matched conflicts are **flagged, not guessed**;
  weaker contradictions lower confidence while keeping the recorded value.

### Background cognition (§13–§14) — `cognition/background.py`

The most tightly constrained feature in the release.

- **bounded**: ≤6 tasks per cycle under a wall-clock deadline
- **cancellable** between tasks
- **rate-limited**: 60 s minimum interval, so a browser refresh cannot trigger
  work
- **non-destructive**: the entire allowed task set only annotates, classifies
  and surfaces
- **controllable**: enable / pause / disable / resume
- **honest**: a cycle that finds nothing records `findings: []`,
  `changes_made: 0` and says *"nothing needed attention"*. There is no code
  path that manufactures activity.

It is not a daemon. Cycles are explicitly invoked and run synchronously under a
deadline; there is no uncontrolled loop anywhere in the module.

### Attention V2 (§15–§16) — `cognition/attention.py`

Wraps the V8.2 scoring engine and adds what it lacked: current-task relevance,
mission context, and a **learned silence policy** built only from recorded
reactions. Silence is never read as consent — with fewer than four recorded
reactions the policy returns `INSUFFICIENT EVIDENCE` and the default cost.

The full ladder is `IGNORE < MONITOR < PREPARE < MENTION < ASK < ACT`, with
`DO_NOTHING` as a legitimate distinct outcome ("real, but not now") separate
from `IGNORE` ("not worth tracking"). Every suppression is recorded with its
reasoning.

### Time machine (§21) — `cognition/timemachine.py`

Reconstructs past state from **stored history only**.

If history does not cover the requested moment the answer is
`HISTORY NOT AVAILABLE`. Current state is never back-projected onto an
unrecorded past. A fact that existed but has no recorded transitions at that
point is reported with `state_at_time: "UNKNOWN"` rather than an assumed value.

### Simulation (§20) — `cognition/simulation.py`

Isolation is structural, not conventional: projection runs against a deep-copied
snapshot holding no reference to live state. Everything produced is tagged
`SIMULATED`. Committing requires **both** `confirm=True` **and** an explicit
list of changes — a simulation id alone can never mutate reality. When a
simulation is committed, the change is recorded in `world_changes` like any
other real change.

### Documents (§6) — `cognition/documents.py`

Lifecycle `INGESTED → PARSED → INDEXED → AVAILABLE → STALE → REPLACED → REMOVED`.

Genuinely parsed: text/markdown/log (`FULL`), CSV/TSV and JSON
(`STRUCTURE ONLY` — shape is read, meaning is not inferred).

`NOT CONFIGURED`: PDF, DOCX, XLSX, PPTX. These are tracked with real metadata
and labelled `METADATA ONLY`. **There is no fake OCR, no invented summary, and
content is never inferred from a filename.**

### Connectors and research (§26–§27) — `cognition/connectors.py`

Interfaces without integrations. Four connectors are declared and all are
`NOT CONNECTED`. The result shape deliberately distinguishes *"there is no
source"* (`items: None`) from *"the source returned nothing"* (`items: []`) —
conflating those would be a lie about the world.

Research tracks questions, claims and contradictions but returns
`RESEARCH PROVIDER NOT CONFIGURED` and generates no findings.

### Maintenance V2 (§23–§24) — `cognition/maintenance.py`

`review()` is read-only, which is what makes it safe to run in a background
cycle; it reports `changes: 0` honestly rather than dressing up diagnosis as
work. Reinforcement **requires a recorded outcome** — retrieval alone is
explicitly refused, because otherwise a frequently-surfaced wrong memory would
make itself look trustworthy over time.

## Persistence

New tables: `missions`, `mission_steps`, `mission_events`, `mission_links`,
`observations`, `background_cycles`, `documents`, `connectors`,
`research_sessions`.

New columns (additive, guarded by `PRAGMA table_info`): world-entity freshness
(`last_confirmed_at`, `freshness_class`, `freshness_reason`, `stale`,
`epistemic_status`), prediction windows (`evaluation_window_days`, `partial`),
intervention context (`mission_id`, `suppressed_because`), sandbox tagging
(`epistemic_status`, `assumptions`).

The V8/V8.1 schema string is untouched; V8.3 DDL lives in a separate
`SCHEMA_V83` constant so that separation is provable.

---

## Events (§3)

The existing bus stays canonical. V8.3 adds 13 categories — `perception.*`,
`world.*`, `mission.*`, `attention.*`, `intervention.*`, `observation.*`,
`outcome.*`, `simulation.*`, `background.*`, `memory.maintenance_*`,
`history.*`, `connector.*`, `research.*` — bringing the vocabulary to **178
types, every one labelled**. The bus rejects unregistered types, so the log
cannot drift.

## Honest limitations

- **No authentication.** MEMORY//OS is single-user and local-first. There is no
  login, no session auth and no multi-tenant isolation beyond the `user_id`
  parameter. This is a deliberate design choice, documented rather than faked.
- **No connectors.** Calendar, email, files and tasks are interfaces only.
- **No research provider.** No web access, no evidence gathering.
- **No PDF/DOCX/XLSX parsing** in this build.
- **No vision model** unless one is configured; images are metadata only.
- **Background cognition is explicitly invoked**, not scheduled. There is no
  timer thread in this build — a deliberate safety choice.
- **The real-model path was not executable in the build environment** (no
  Ollama reachable). It is covered by scripted-model tests and the
  deterministic fallback was verified end-to-end.
