# V8.1 → V8.2 — Cognitive Core

V8.2 does not add features on top of V8.1. It makes the cognition that V8.1
*described* actually **run, be recorded, and be inspectable** — and it makes the
system refuse to claim anything it has not observed.

Nothing in V8/V8.1 was removed. Every V8.1 endpoint, response field and test
still works; the V8.2 additions are strictly additive.

---

## The one-sentence summary

> V8.1 could tell you what it believed. V8.2 can tell you **why it believed it,
> what that belief actually changed, and whether it turned out to be right** —
> and where it cannot tell you, it says `INSUFFICIENT EVIDENCE` instead of
> guessing.

---

## 1. What actually changed

### §3 Real model routing with capability detection
`app/providers/capabilities.py` (new)

Capabilities are **detected**, not assumed. Five capabilities (`generation`,
`structured_output`, `tool_calling`, `vision`, `embeddings`) are resolved from
the provider status *and* a known-model table, and every state carries the
reason it was assigned.

Three states, deliberately:

| State | Meaning |
|---|---|
| `SUPPORTED` | Verified from the provider + a known model profile |
| `NOT_SUPPORTED` | Positively known to be unavailable |
| `UNKNOWN` | The model is not in the capability table |

`UNKNOWN` **never satisfies a requirement**. An unrecognised model is not
optimistically assumed to call tools.

The provider can veto a capable model: if the provider cannot bind tools, a
tool-capable model still reports `tool_calling: NOT_SUPPORTED`.

The `CapabilityRouter` then maps each task class onto how it will *actually*
run:

```
conversation           DETERMINISTIC    degraded=True
memory_retrieval       DETERMINISTIC    degraded=True
structured_extraction  DETERMINISTIC    degraded=True
tool_execution         DETERMINISTIC    degraded=True
vision                 NOT_CONFIGURED   degraded=True
embedding              MODEL            degraded=False
```

Note `vision`: there is no honest deterministic fallback for vision, so it is
reported `NOT_CONFIGURED` rather than quietly downgraded.

### §4 A genuinely model-driven agent loop
`app/agent/execution.py` (new), `app/agent/graph.py` (rewritten)

The loop is now traced end-to-end with eleven stages: `MODEL_CALL`,
`TOOL_DECISION`, `TOOL_RESULT`, `MODEL_REVISION`, `FINAL_RESPONSE`,
`CONTEXT_BUILD`, `PROVIDER_DEGRADED`, `CANCELLED`, `LIMIT_REACHED`,
`TOOL_FAILED`, `DUPLICATE_TOOL_CALL`.

Four safety properties, each test-covered:

- **Depth cap** (`MAX_TOOL_DEPTH`, default 4) — a looping model is stopped.
- **Timeout** (`TURN_TIMEOUT_S`, default 180).
- **Duplicate-call detection** — an identical `(tool, args)` pair is blocked and
  reported to the model rather than re-executed.
- **Cancellation** — a cooperative token checked between steps.

When the loop stops early it **says so** instead of returning an empty reply:

> "I stopped before finishing this one: the model exceeded the maximum of 2 tool
> rounds. I did not produce a final answer, so nothing here is guessed."

A tool failure is recoverable, not fatal: the error is handed back to the model
as `TOOL_ERROR: …` so it can adapt.

### §5 / §16 Canonical context builder and context fabric
`app/cognition/context_builder.py` (new)

One bounded, relevance-ranked, provenance-carrying context bundle per turn.
Per-section caps (memories 6, world 6, goals 4, commitments 4, decisions 3,
predictions 3, episodic 6, preferences 4) and a 4 000-character global cap.
Truncation is **declared**, never silent. A failing section degrades that
section only and is named in `notes`.

Every item carries `kind`, `source`, `relevance`, `confidence`, `reason` and
`permission`. `confidence: null` is a legitimate honest value for subsystems
that record no confidence — it is never faked as a number.

External sources are declared as **NOT CONNECTED** with a reason, and
contribute zero context items. The prompt says so out loud:
`Not available to me: calendar, email, files.`

### §6 / §7 Memory Arbitration V2 and retrieval quality
`app/cognition/arbitration.py` (new)

Nine weighted factors (confidence, recency, authority, reputation,
specificity, scope, freshness, explicit-correction, minus a contradiction
penalty) produce a score that is always accompanied by the evidence behind it.
Every arbitration is persisted with winner, losers, blocked candidates, the
reason and an uncertainty value.

Key guarantees:
- Confidence and reputation stay **separate fields**.
- A `superseded` memory is blocked outright, with the reason given.
- A memory whose lifecycle is `retired` or `quarantined` is excluded from
  retrieval and reported in `excluded`, not silently dropped.
- All-blocked candidates yield `INSUFFICIENT EVIDENCE`, not an arbitrary winner.

### §8 The causal chain: memory → influence → outcome → reputation
`app/cognition/influence.py` (new)

This is the heart of V8.2's honesty.

- **Retrieval is not influence.** Retrieving a memory records a usage count and
  nothing else. Reputation does not move.
- Only the **arbitration winner** is recorded as influencing a turn.
- An outcome with **no evidence** is downgraded to `INSUFFICIENT EVIDENCE` and
  reputation stays put — even if the caller claimed `SUPPORTED`.
- `NEUTRAL` never moves reputation.
- An influence with no observed outcome reads *"Influenced N decision(s), but no
  outcome has been observed — INSUFFICIENT EVIDENCE to judge it."*

### §9 Continuity engine
`app/cognition/continuity.py` (new)

Nine grounded reasons to return to something (`active_project`,
`unfinished_commitment`, `recent_decision`, `prior_conversation`,
`pending_question`, `open_prediction`, `recent_failure`, `at_risk`,
`next_step`), with decay to dormant after 45 days.

### §10 / §11 Intent evolution V2 and need detection V2
`app/cognition/intent_v2.py` (new)

**A question never creates an intent fact.** `"should I migrate to Postgres?"`
asserts nothing; it is reported as a question and the existing intent is
untouched.

Intent changes are probabilistic and always carry `uncertainty` and
`changed_because` with the quoted evidence.

A deliberate design decision, made because the alternative was dishonest: when
a second objective appears **without** an explicit change signal, it is recorded
as `emerging` and surfaced separately as `emerging_intent`. It does **not**
demote the objective the user actually confirmed. Only an explicit change or
resume signal supersedes.

Needs (11 of them) are always labelled `hypothesis: true` with a confidence
below 1.0. `accuracy()` returns `INSUFFICIENT EVIDENCE` until real feedback is
recorded.

### §13 Prediction → reality → learning
`app/cognition/prediction.py` (`observe()` is new)

A prediction is **only** scored when the observation genuinely resolves it.
Mentioning the topic is not evidence:

```
observe(p, "I was thinking about the migration today")
  → resolved: False, "INSUFFICIENT EVIDENCE — that observation does not
    clearly confirm or refute this prediction, so it remains open."
```

When it *is* resolved, we compute `error`, `surprise` (error weighted by how
sure we were — confidently wrong is the only genuinely surprising outcome) and
a plain-language `learning_signal`, all persisted.

### §14 Consequence and regret
`app/cognition/causality.py`

Regret is **evidence-based or absent**:

- Positive outcome → `0.0`.
- Negative outcome with no recorded expectation, no cited evidence and no
  opportunity cost → **regret is `None`**, labelled `INSUFFICIENT EVIDENCE`.
  *A bad result is not by itself proof of a bad decision.*
- Otherwise the score is built from what can be pointed at: a violated explicit
  expectation (+0.5), cited evidence (+0.15 each, capped 0.3), a concrete
  opportunity cost (+0.2).

Second-order effects, delayed consequences and opportunity cost stay `NULL`
when unobserved — an unobserved consequence is not the same as no consequence.

### §15 / §17 Adaptive policy and per-capability trust
`app/cognition/policy_engine.py`, `app/cognition/trust_v2.py` (both new)

Eight behavioural dimensions, each learned only from real observations, each
carrying its evidence, each revertible. Eight capabilities tracked per task
class with Laplace smoothing, `MIN_EVIDENCE=3` and suppression after three
consecutive failures. Below the evidence threshold the label is
`INSUFFICIENT EVIDENCE` and `reliability` is `null` — not an optimistic default.

### §19 User-controlled cognition
`app/cognition/user_control.py` (new)

Seven natural-language commands: `FORGET`, `CORRECT`, `REMEMBER`,
`EXPLAIN_BELIEF`, `EXPLAIN_BEHAVIOUR`, `STOP_TOPIC`, `PRIORITISE`.

Two rules make this safe:

1. **Strict phrasing only.** `"I forgot to mention the deploy window"` and
   `"what should I remember for the meeting"` are ordinary conversation and
   change nothing. Patterns are imperative-anchored.
2. **Never guess a destructive target.** `"forget that"` with nothing in focus
   and no description refuses:
   > *"I could not tell which item you meant — nothing is currently in focus,
   > so I did not guess."*

   Two near-equal search matches also refuse rather than pick one.

### §20 Autonomy governor V2
`app/cognition/autonomy.py`

The binary act/ask becomes five dispositions, while `decision` stays act/ask for
backwards compatibility:

| Disposition | Meaning |
|---|---|
| `ACT` | Low risk, reversible, within your autonomy level |
| `ASK` | Could do it, but the risk exceeds unilateral authority |
| `WAIT` | Not enough evidence yet to act *or* ask a useful question |
| `DO_NOTHING` | Observe-only mode: staying out of the way is correct |
| `BLOCKED` | Irreversible/external, or a demonstrably poor track record |

### §21 Object permanence
`app/cognition/focus.py` (new)

Stable-ID resolution with a 30-minute TTL, scoped per session. A bare deictic
("forget **that**") resolves only when exactly one object is focused; with two,
it reports ambiguity rather than choosing.

### §23 Explanation endpoints
`why`, `why-now`, `what-changed`, `why-used` — all answered from recorded
evidence. **No hidden chain-of-thought is ever exposed**; explanations cite
sources, confidences, reputations and transitions.

| `intent_transitions` | Why intent changed, with evidence |

| `world_changes` | World-model deltas |
| `capability_trust` | Per capability × task class reliability |
| `execution_traces` | Per-turn agent execution steps |
| `continuity_items` | Open threads worth returning to |

`predictions(expected_evaluation_at, error, surprise, learning_signal)`;
`intents(uncertainty, previous_intent_id)`;
`decisions(second_order, delayed_consequences, opportunity_cost, regret_evidence)`.

### Bugs this work caught

The tests were written to be capable of failing, and several did:

1. **Empty reply on depth limit** — when the loop hit `MAX_TOOL_DEPTH` mid
   tool-call, `run()` returned `""`. Now it explains why it stopped.
2. **Emerging intent overwrote the confirmed one** — a second objective was
   stored as `emerging` but *reported* as `current_intent`. Fixed to surface it
   as `emerging_intent`.
3. **"back to X" was discarded** — an explicit resume signal with no
   purpose-phrase fell through to "no statement of purpose". Added `_try_resume`,
   which still refuses when the target is ambiguous.
4. **REMEMBER false positive** — `"what should I remember for the meeting"`
   triggered a memory write. The pattern is now imperative-anchored.
5. **Test isolation** — a shared LangGraph thread leaked messages between tests.

## 7. What V8.2 still does not do

- It does not learn across users. All cognition is per-user-namespace.
- Continuity decay is time-based, not semantic.
- Need detection is regex-signal based with context reinforcement; with a real
  model configured, structured extraction augments it, but the rule baseline
  always runs underneath.
- The context fabric has the permission-aware *shape* for external connectors
  but **no connectors**. `UNCONNECTED` is a valid, honest end state.
- Regret is scored from what the caller supplies as evidence; the system does
  not independently investigate the world to find that evidence.
