# V8.4.4 Verification — Data Portability + Export + Recovery

Verification is recorded from the V8.4.4 working tree. Claims below are based
on commands run against the repository, not simulated release state.

  — **7 passed**.

## Security gates

The package validator was checked for:

- maximum package/member/decompressed size, record count, relationship count,
processing deadline and nesting depth;
- absolute, parent-traversal and backslash filenames, duplicate entries and
symlinks;
- malformed ZIP, UTF-8 and JSON;
- unknown schema versions, tables and columns;
- per-file and per-object SHA-256 mismatch;
- missing primary keys, user-scope mismatch and dangling relationships;
- instruction-like imported strings remaining inert warnings;
- no pickle, eval, import execution or arbitrary serialized objects.

A rejected validation writes a `portability_validation_results` record and emits
`import.rejected`; it does not insert/replace/delete live cognitive records.

## Clean-room and artifact gate

The final verification also runs the release ZIP script against the source tree,
extracts the ZIP into a fresh directory, creates a fresh Python environment,
runs the complete backend suite, runs fresh `npm ci`, typecheck, lint and build.
The release ZIP excludes `.git`, dependency/build/cache directories, runtime
SQLite/Chroma state, secrets and temporary files while retaining legitimate
`.svg`, `.webp`, and `.ico` assets.

Final artifact names:

- `memory-os-showcase-V8.4.4-DATA-PORTABILITY-EXPORT-RECOVERY-FINAL.zip`
- `memory-os-showcase-V8.4.4-DATA-PORTABILITY-EXPORT-RECOVERY-FINAL.zip.sha256`

The SHA-256 sidecar is generated from the final ZIP bytes and is checked with
`sha256sum -c`.

Observed artifact gate: **289 files**, CRC `OK`, and the generated sidecar
passes `sha256sum -c`. The ZIP contains the V8.4.4 docs, portability service,
migration, API/tool tests and Observatory surface; no prohibited dependency,
database, secret or cache path was present.
