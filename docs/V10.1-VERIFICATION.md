## 7. Known limitations

- Relevance phrase vocabularies (conflict query, explicit audit,
  outcome-marker normalisation) are English-only; canonical-object triggers
  are language-independent.
- Prediction↔outcome and unknown↔evidence matching require both sides to
  project to a canonical proposition with matching subject+predicate; a
  non-proposition-shaped outcome yields no link (honest UNKNOWN rather than
  a guessed match).
- The bounded re-audit runs when a confirmation arrives through the public
  confirm endpoint; direct internal `MaintenanceProposalService.confirm()`
  calls (tests, tools) do not implicitly re-audit — callers opt in via
  `maintenance_runtime.reaudit_after_confirmation`.
- Real-model behavior of the whole V10.1 loop is unverified in this
  environment (NOT CONNECTED).

## 8. PR #14 correctness fix — verification

Three coupled correctness bugs were fixed in one commit on this branch
(no history rewrite):

1. **Proposal visibility.** `run_for_turn` previously captured only the
   audit's proposals before the prediction-outcome / unknown-evidence
   matchers ran, so matcher-created proposals existed canonically but were
   invisible in the turn context (status claimed
   `MAINTENANCE_COMPLETED_WITH_FINDINGS` while a proposal silently waited).
   Now all proposals created inside the bounded turn are merged (dedup by
   canonical id) and `WAITING_FOR_CONFIRMATION` is reported whenever ≥1
   PROPOSED/DEFERRED proposal exists.
2. **RECORD_OUTCOME canonical apply.** `MaintenanceProposalService._apply`
   had no RECORD_OUTCOME branch, so confirming the flagship V10.1 proposal
   always ended BLOCKED. It now applies through the canonical
   `PredictionEngine.observe()` (single evaluation authority): real
   observation text from the evidence refs, engine resolution-signal rules
   preserved, APPLIED only when the engine actually resolves; insufficient
   evidence stays honestly BLOCKED with the engine's reason and the
   prediction stays open — no fabricated verdict, no duplicate outcome
   storage.
3. **Trigger-aware re-audit.** `reaudit_after_confirmation` hard-coded
   families (debt, contradictions, unknowns), so a confirmed prediction
   outcome never re-audited `model_errors`. Families are now derived
   deterministically from the proposal type (`REAUDIT_FAMILY_MAP`);
   RECORD_OUTCOME → (model_errors, debt). Depth 1, idempotency, and the
   `::reaudit1` bound are unchanged.

Regression tests added (all PASS, part of the 34-test focused suite):

- `test_record_outcome_proposal_is_visible_in_turn_context`
- `test_confirm_unknown_proposal_is_visible_in_turn_context`
- `test_confirmed_record_outcome_resolves_prediction_canonically`
- `test_record_outcome_with_insufficient_evidence_is_blocked_not_applied`
- `test_record_outcome_reaudit_targets_model_errors_family`
- `test_record_outcome_flow_causes_no_recursive_maintenance_storm`
