# MEMORY//OS V8.5 — Security Model

This document describes what is actually enforced, where, and what is out of
scope. Claims below are backed by the automated suites listed in
`docs/V8.5-VERIFICATION.md`.

## Threat model

In `AUTH_MODE=required` the system defends against:

- **Credential attacks**: brute force (per-client auth rate limit), credential
  stuffing (uniform failures, PBKDF2-HMAC-SHA256 at 600k iterations),
  account-existence probing (identical error + comparable timing for unknown
  accounts).
- **Session attacks**: theft of the database does not yield usable tokens
  (SHA-256-hashed storage); fixation is impossible (new token per login);
  logout/revocation/disablement kill sessions immediately; expiry is enforced
  server-side; the cookie is HttpOnly + SameSite=lax (+ Secure in
  production).
- **CSRF**: cookie-authenticated mutations require the per-session
  `X-CSRF-Token` header, compared in constant time. Bearer requests carry no
  ambient credential and are exempt.
- **IDOR / namespace escape**: the namespace is resolved once from the
  verified session; caller-supplied user ids are ignored at every surface
  (query, body, tools). Bare-id object routes return 404 on ownership
  mismatch, revealing neither data nor existence. Cross-user thread-id reuse
  at `/api/chat` is refused so LangGraph checkpoints cannot resume a foreign
  dialogue.
- **Privilege escalation**: strict request schemas (`extra="forbid"`) close
  mass assignment; role grants are permission-gated (admins cannot mint
  admins/owners; only owners manage roles; self-disable/self-demote are
  refused); cross-tenant admin actions answer 404.
- **Resource abuse**: global body-size cap, portability's byte-accurate
  package caps, bounded rate limits per category with observable violations.
- **Information leakage**: production-safe error envelope (no stack traces,
  no paths); secret-shape redaction on error messages and JSON logs; metrics
  labels are route templates only; audit payloads carry redacted emails and
  identifiers, never credentials, tokens or memory content.

## Out of scope / honest limits

- TLS termination, network policy, and OS hardening belong to the deployment.
- Rate limiting and metrics are per-process; a load-balanced deployment needs
  shared backends for both.
- No MFA, no password reset flow, no email verification (no mail dependency
  exists; adding one must report honest NOT_CONFIGURED state).
- The audit trail protects integrity by application convention (append-only
  usage of `cognitive_events`), not by cryptographic chaining.
- `AUTH_MODE=disabled` is intentionally not a security boundary: it is the
  V8.4.4-compatible local single-user mode and says so in the UI.

## Data classes, visibility and retention

| Class | Examples | Visibility | Retention |
|---|---|---|---|
| User-generated | messages, memories, missions | owner namespace only | until user deletes / retires |
| Derived cognitive | skills, principles, predictions, explanations | owner namespace only | lifecycle-managed by the cognitive layer |
| Imported | staged packages, restored rows | owner namespace only; ownership re-validated | staged packages kept for audit; restores logged |
| External research evidence | fetched pages, claims | owner namespace only | session-scoped, never cross-tenant |
| System telemetry | metrics, request logs | operators (`health.read`); content-free | in-memory, resets on restart |
| Security audit | auth/authz/session events | tenant admins (`security.read`) | append-only in `cognitive_events` |
| Configuration | env-derived settings | operators; secrets never echoed | environment lifetime |
| Secrets | passwords, session tokens, API keys | never stored in recoverable form; never logged, exported or displayed | hashes only |

## Secret handling

- No secrets in source or `.env.example` (placeholders only) — enforced by a
  static secret-scan test that runs over the repository in CI/pytest.
- Runtime secrets come exclusively from the environment
  (`AUTH_BOOTSTRAP_EMAIL/PASSWORD`, `OPENAI_API_KEY`).
- Passwords: salted PBKDF2-HMAC-SHA256, configurable cost, constant-time
  verification. Session tokens: 256-bit random, stored as SHA-256 hashes.
- Log and error redaction masks common secret shapes
  (`password=…`, `api_key=…`, `Bearer …`, `sk-…`).
- Release ZIPs exclude env files, keys, certificates, databases and caches.

## Enforcement points

1. **`production_trust_middleware`** (`app/main.py`) — the single choke
   point: request id, body bound, session verification, CSRF, rate limits,
   latency metrics, safe 500s. Runs before every `/api` route.
2. **`uid()`** — namespace resolution; ignores caller-supplied identity when
   auth is required.
3. **`ensure_owner()`** — object-level ownership on bare-id routes.
4. **`require_permission()`** — RBAC gate; denials are audited.
5. **`IdentityService`** — all user/tenant/session state transitions, all
   audited on the canonical EventBus.
6. **Strict schemas** (`app/schemas/security.py`) — `extra="forbid"`,
   bounded fields, no mass assignment.
