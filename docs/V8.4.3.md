# MEMORY//OS V8.4.3 — Connected Research + External World Intelligence

V8.4.3 adds a real, additive research capability: the system can fetch
explicit http(s) URLs — supplied by the user or a tool call, never invented
— through an SSRF-defended pipeline, and turn what it genuinely retrieves
into auditable, provenance-carrying evidence and bounded-confidence claims.
It does **not** add a search engine, does **not** auto-promote external
content into memory, and does **not** replace the V8.3 `ResearchMode` /
`ConnectorRegistry` honest "NOT CONFIGURED" contract, which is preserved
byte-for-byte.

```text
 EXPLICIT URL (user or tool call)
        ↓
 net_security.fetch()  — SSRF defense, redirect re-validation, resource limits
        ↓
 SOURCE  (one row per canonical URL fetched in a session)
        ↓
 FETCH   (the audit ledger — every attempt, success or failure, is recorded)
        ↓
 content_safety — prompt-injection detection (flag, never execute)
        ↓
 EVIDENCE  (deterministic sentence-level excerpts, with strength/quality/freshness)
        ↓
 CLAIM     (deterministic corroboration/conflict grouping, capped confidence)
        ↓
 CONFLICT  (both sides always preserved — never silently resolved)
        ↓
 WORLD UPDATE (explicit propose → confirm=True → apply, via WorldStateV2.reconcile)
        ↓
 EXPLANATION ENGINE (explain_research_* — RESEARCH_EVIDENCE / RESEARCH_CONFLICT classes)
```

## Non-negotiables, and how they are enforced

| Principle | Enforcement |
|---|---|
| No fabricated URLs | `fetch_research_source` never invents a URL; the system prompt and every research tool description say so explicitly; only URLs the caller supplies are ever fetched |
| Failure is first-class | Every fetch attempt — success, `FETCH_FAILED`, `BLOCKED`, `TIMEOUT` — is persisted in `research_fetches`; nothing is silently dropped or rendered as "no information found" |
| Evidence ≠ belief | Evidence rows are raw excerpts (`research_evidence.excerpt`) with no confidence-to-truth mapping; claims are a *separate*, explicitly-derived layer with a capped `claim_confidence` |
| Confidence dimensions kept separate | `source_quality`, `evidence_strength`, `freshness`, `corroboration_count`, `independent_domain_count`, `claim_confidence` are distinct fields — never collapsed into one number |
| SSRF defense mandatory, multi-stage | `net_security.validate_url_syntax` (pre-DNS) + `resolve_and_pin` (post-DNS) + per-redirect re-validation on every hop, including the initial and every subsequent hop |
| No prompt-injection execution | `content_safety.scan()` flags imperative/instruction-like patterns in fetched text; flags are surfaced (`injection_flags`) but fetched content is **never** interpreted as instructions by the agent |
| Deterministic claim/conflict extraction, honestly labeled | `research.py` module docstring and `status()` response state plainly that extraction is sentence-splitting + lexical similarity (`SequenceMatcher`), not semantic understanding |
| World Model updates bounded and explicit | `propose_world_update` creates a `PROPOSED` row only; `apply_world_update` requires `confirm=True`, cannot double-apply (raises `ValueError`), and routes through the existing `WorldStateV2.reconcile()` — never a parallel world-state mechanism |
| No auto-promotion to memory/skill/principle | Nothing in the research pipeline writes to `memories`, `knowledge_items`, or `experiences`; the only downstream integration point is the explicit, confirmed World Model update path above |

## Data model (SQLite, additive only)

All tables are `CREATE TABLE IF NOT EXISTS`, scoped by `user_id`, and named
to avoid any collision with the pre-existing V8.3 `research_sessions` table
(hence `research_sessions_v2`).

- **`research_sessions_v2`** — one research question/investigation.
  `id, user_id, question, state (DRAFT/RUNNING/PARTIAL/COMPLETED/BLOCKED/FAILED), provider_state, correlation_id, source_count, evidence_count, claim_count, conflict_count, open_questions, detail, created_at, updated_at`
- **`research_sources`** — one row per canonical URL fetched in a session.
  `id, session_id, user_id, canonical_url, domain, title, publisher, source_type, source_quality, availability, metadata, discovered_at, created_at`
- **`research_fetches`** — the fetch ledger; **every** attempt, including failures.
  `id, session_id, user_id, source_id, requested_url, final_url, status, http_status, content_type, latency_ms, redirect_count, redirect_chain, content_hash, bytes_read, error_code, error_detail, correlation_id, fetched_at, created_at`
- **`research_evidence`** — raw excerpts, never beliefs.
  `id, session_id, user_id, source_id, fetch_id, excerpt, locator, evidence_type, evidence_strength, source_quality, freshness, injection_flags, retrieved_at, content_hash, created_at`
- **`research_claims`** — deterministically derived, capped-confidence statements.
  `id, session_id, user_id, statement, evidence_ids, source_ids, evidence_strength, source_quality, corroboration_count, independent_domain_count, freshness, claim_confidence, conflict_group, status (supported/contested/unsupported), created_at, updated_at`
- **`research_conflicts`** — both sides of a detected contradiction, always preserved.
  `id, session_id, user_id, conflict_group, claim_ids, subject_key, reason, created_at`
- **`research_world_updates`** — explicit, confirmable bridge to the World Model.
  `id, session_id, user_id, claim_id, world_entity_id, kind, label, proposed_confidence, applied_confidence, state (PROPOSED/APPLIED/REJECTED), reason, correlation_id, created_at, resolved_at`

A dedicated migration test (`tests/test_v843_migration.py`) proves a
genuine pre-V8.4.3 (V8.4.2-shaped) database file opens cleanly under
V8.4.3 startup: all pre-existing rows across `memories`, `missions`,
`world_entities`, `world_changes`, `knowledge_items`,
`explanation_snapshots`, and `cognitive_events` remain intact and
untouched, and the seven new tables above are created for the first time,
idempotently.

## Network security (`net_security.py`)

- **Allowed schemes**: `http`, `https` only. Everything else (`ftp://`,
  `javascript:`, etc.) is rejected as `UNSAFE_SCHEME`.
- **Allowed ports**: `80, 443, 8080, 8443`. Anything else is
  `PORT_NOT_ALLOWED`.
- **Userinfo rejected**: `http://user:pass@host/` → `USERINFO_REJECTED`.
- **Structural (pre-DNS) validation** rejects: whitespace/invalid characters
  in the hostname, literal IPv4/IPv6 loopback/private/link-local/multicast/
  CGNAT/unspecified addresses, IPv4-mapped IPv6 embeddings
  (`::ffff:127.0.0.1`), and alternate IPv4 literal encodings used to evade
  naive string checks (decimal `2130706433`, hex `0x7f000001`, partial
  dotted `127.1`).
- **Post-DNS validation + connection pinning**: `resolve_and_pin()` resolves
  the hostname, classifies **every** resolved address with the same
  `ipaddress`-based checks, and — critically — the actual socket connection
  is pinned to the exact validated IP (`_PinnedHTTPConnection` /
  `_PinnedHTTPSConnection` override `connect()` to call
  `socket.create_connection((pinned_ip, port))` directly, while still
  presenting the correct `Host` header / TLS SNI). This is what defeats
  **DNS rebinding**: the IP that was checked is the IP that is actually
  connected to, not re-resolved.
- **Every redirect hop is re-validated** from scratch through the full
  pre-DNS + post-DNS pipeline — a redirect to a private address is blocked
  exactly like a direct request to one would be.
- **Resource limits**: `CONNECT_TIMEOUT_S=6.0`, `READ_TIMEOUT_S=10.0`,
  `OVERALL_TIMEOUT_S=20.0`, `MAX_REDIRECTS=5`,
  `MAX_RESPONSE_BYTES=2_000_000`; only text-ish content types
  (html/json/xml/plain-text family) are accepted, anything else is
  `UNSUPPORTED_CONTENT_TYPE`.
- **`FetchResult`** always carries: `ok, requested_url, final_url, status
  (COMPLETED/FETCH_FAILED/BLOCKED/TIMEOUT), http_status, content_type,
  body_text, bytes_read, redirect_chain, redirect_count, latency_ms,
  error_code, error_detail, content_hash` (a real SHA-256 of the fetched
  bytes) — `fetch()` **never raises** on bad/malicious input; it always
  returns a `FetchResult` describing what happened.

## Content safety (`content_safety.py`)

Fetched page text is treated as **untrusted data, never as instructions**.
A pattern-based scan flags imperative/instruction-like language commonly
used in prompt-injection attempts (e.g. "ignore previous instructions",
"you are now", "system:") found inside fetched content. Flags are recorded
on the evidence/fetch result (`injection_flags`) and surfaced to the user —
the agent's system prompt is explicit that such content must never be
followed, only reported as flagged untrusted text.

## Evidence, claim and conflict model

- **Evidence** is produced by deterministic sentence splitting of the
  fetched page's extracted text, bounded to `MIN_CLAIM_CHARS=20` /
  `MAX_CLAIM_CHARS=320` characters, capped at `MAX_EVIDENCE_PER_FETCH=3`
  excerpts per fetch. Each evidence row carries `evidence_strength`,
  `source_quality`, and `freshness` (`FRESH`/`AGING`/`STALE` based on
  retrieval recency), plus full provenance (`source_id`, `fetch_id`,
  `locator`, `content_hash`).
- **Claim matching** compares a new candidate statement against existing
  claims in the session using `SequenceMatcher` word-level similarity
  (`CORROBORATE_SIMILARITY=0.85`). A near-identical restatement **with the
  same factual values** (dates/numbers extracted via `_value_tokens`) is
  treated as corroboration of the same claim; a near-identical restatement
  **with different values** (e.g. two dates) is never silently merged — it
  is instead evaluated for conflict.
- **Corroboration counts independent domains, not repeated pages**:
  `corroboration_count` and `independent_domain_count` only increase when a
  claim is confirmed from a **different** source domain — fetching two
  pages from the same site never inflates confidence.
- **Conflict detection** (`CONFLICT_KEY_SIMILARITY=0.82`) identifies claims
  that share a subject/lexical key but disagree on the factual value, and
  creates a `research_conflicts` row referencing **both** claim ids —
  neither claim is discarded or silently "resolved."
- **Confidence formula** (`_claim_confidence`):
  `raw = 0.20 + 0.15*evidence_strength + 0.15*source_quality + 0.08*min(max(independent_domain_count-1,0),3)`,
  then capped at `SINGLE_SOURCE_CONFIDENCE_CAP=0.55` for single-domain
  claims or `CORROBORATED_CONFIDENCE_CAP=0.80` once corroborated from more
  than one independent domain. A separate, lower
  `WORLD_UPDATE_CONFIDENCE_CAP=0.60` bounds anything that reaches the World
  Model.
- **Session limits**: `MAX_SOURCES_PER_SESSION=10`,
  `MAX_CLAIMS_PER_SESSION=40` — enforced honestly (further fetches/claims
  are refused with an explicit reason once reached, not silently dropped).

## World Model integration

A claim can influence the World Model only through two explicit,
separately recorded steps:

1. `propose_world_update(user_id, session_id, claim_id, kind, label)` —
   creates a `research_world_updates` row with `state="PROPOSED"` and a
   `proposed_confidence` capped at `WORLD_UPDATE_CONFIDENCE_CAP`. **This
   never touches the World Model itself.**
2. `apply_world_update(user_id, update_id, confirm=True)` — requires the
   caller to pass `confirm=True` explicitly (an unconfirmed or `confirm=False`
   call raises `ValueError`/`400`); on success it calls the **existing**
   `WorldStateV2.reconcile()` with `source="research"`, so it flows through
   the same keep/supersede/merge/flag/downgrade/ignore verdict logic every
   other subsystem uses. A world entity created this way is tagged
   `source="research"` and carries the capped confidence — it is visibly
   distinguishable from user-stated or inferred facts in the Observatory
   World panel. Applying an already-applied update raises `ValueError`
   (no silent no-op, no double-apply).

## Event vocabulary (added to the existing `EventBus`)

New `research.*` event types were added to the *same* `EVENT_TYPES`
frozenset and `LABELS` dict in `app/cognition/events.py` — there is no
second event bus. Events cover session lifecycle, fetch attempts (success
and failure), evidence/claim creation, corroboration, conflict detection,
and world-update propose/apply, each emitted through the canonical
`bus.emit(...)` used everywhere else in the codebase, and independently
queryable via `bus.for_subject("research_session", ...)` /
`bus.for_subject("research_claim", ...)` like any other subject kind.

## API routes (`/api/research/v2/*`)

A **distinct, additive namespace** from the legacy `/api/research` route
(which is untouched and still returns the honest `BLOCKED` /
`RESEARCH PROVIDER NOT CONFIGURED` state):

| Method & path | Purpose |
|---|---|
| `GET /api/research/v2/status` | Engine availability, limits, and an honest statement that no search engine exists |
| `POST /api/research/v2` | Create a research session for a question |
| `GET /api/research/v2` | List a user's research sessions |
| `GET /api/research/v2/{session_id}` | Get one session |
| `POST /api/research/v2/{session_id}/fetch` | Fetch one explicit URL (never invented) into the session |
| `POST /api/research/v2/{session_id}/finish` | Mark a session COMPLETED/FAILED based on real fetch outcomes |
| `GET /api/research/v2/{session_id}/sources` | List sources discovered in the session |
| `GET /api/research/v2/{session_id}/fetches` | The full fetch ledger, including failures |
| `GET /api/research/v2/{session_id}/evidence` | List raw evidence excerpts |
| `GET /api/research/v2/{session_id}/claims` | List derived, capped-confidence claims |
| `GET /api/research/v2/{session_id}/conflicts` | List detected conflicts (both sides preserved) |
| `GET /api/research/v2/{session_id}/world-updates` | List proposed/applied world updates for the session |
| `POST /api/research/v2/{session_id}/world-updates/propose` | Propose a bounded world-model update from a claim |
| `POST /api/research/v2/world-updates/{update_id}/apply` | Apply a proposed update (`confirm=True` required) |

Every route resolves the caller's `user_id` via the existing `uid()`
helper, 404s on cross-user or nonexistent ids, and maps `ValueError` to
`400` — exactly the conventions already used by every other route in
`main.py`.

## Conversational cognitive tools

Six new tools were registered in `build_cognitive_tools()` alongside the
existing tool set, following the same epistemic-status and sentinel-value
conventions (`RECORDED`/`NO_RESEARCH_RECORDED`/`AMBIGUOUS`, etc.):

- **`start_research(question)`** — creates a research session; description
  states plainly that no search engine exists and URLs must come from the
  user or be already known, never invented.
- **`fetch_research_source(url, session_id=None)`** — fetches one explicit
  URL; resolves the session by id, conversational focus, or single active
  session; description explicitly says "never invent a URL."
- **`list_research()`** — lists the user's research sessions.
- **`inspect_research(session_id=None)`** — session detail (state, counts,
  detail message).
- **`inspect_research_evidence(session_id=None)`** — raw evidence, labeled
  as excerpts, not conclusions.
- **`inspect_research_claims(session_id=None)`** — claims with their capped
  confidence and corroboration/conflict status, explicitly noting
  confidence is capped, not verified truth.

Session resolution (`_resolve_research_session`) follows the same pattern
as `_resolve_mission`: explicit id → conversational focus
(`cognition.focus.current(...)` filtered to `subject_kind=="research"`) →
single-session auto-resolve → ambiguous-candidate listing → honest
`NO_RESEARCH_RECORDED`.

## Explanation engine integration

`ExplanationEngine` gained `RESEARCH_EVIDENCE` and `RESEARCH_CONFLICT`
explanation classes and `explain_research_*` methods, dispatched from the
*same* `explain()` entrypoint used by every other subject kind
(`subject_kind="research_claim"` / `"research"`). Every explanation returns
the identical shape used across the engine (`summary`, `decisive_factors`,
`supporting_evidence`, `counter_evidence`, `causality`, `timeline`,
`provenance`, ...). A `claim_confidence` decisive factor explicitly states
that the value is *capped*, not a verified fact — carrying the "evidence ≠
belief" principle through into the explanation layer itself. When asked
about unknown/nonexistent research subjects, the engine falls back to the
existing `_insufficient_evidence` path rather than fabricating an answer.

## System prompt guidance

`app/agent/graph.py`'s `SYSTEM_PROMPT` gained a "CONNECTED RESEARCH"
section explaining: there is no search engine; URLs must be user-supplied
or already known, never invented; evidence is not the same as an
instruction or a memory; failures must be reported to the user verbatim
(not softened into "I couldn't find anything"); claim confidence is capped,
not verified fact; conflicting claims from different sources are both kept
and both reported.

## Frontend: Observatory Research surface

`components/observatory/ResearchPanel.tsx` was added to the Observatory
page (`app/observatory/page.tsx`), following the same `Panel`/`StateBadge`/
`Meter`/`Empty` primitives every other Observatory panel uses. It is
deliberately built around visually distinct registers so a **source**, an
**evidence excerpt**, a **claim**, and a **world update** never look like
the same kind of thing:

- Sessions list with per-session state badges.
- A **fetch ledger** that always shows failed/blocked attempts with their
  exact `error_code`/`error_detail` — a blocked SSRF attempt or a timeout
  renders as a clearly negative-toned badge, never rendered as if nothing
  happened.
- **Sources** as plain rows (title/domain/availability).
- **Evidence** rendered as italicized quoted excerpts with a "from
  {locator}" byline — visually distinct from claims — and an explicit
  `INJECTION ATTEMPT FLAGGED (NOT EXECUTED)` badge when
  `injection_flags` is non-empty.
- **Claims** rendered with a confidence meter explicitly labeled "capped,
  externally sourced" plus corroboration/independent-domain counts, and a
  "Propose world update" action.
- **Conflicts** rendered in a warning tone, explicitly stating both
  conflicting claims are preserved.
- **World updates** rendered with PROPOSED/APPLIED state and a "Confirm &
  apply" action that requires an explicit browser confirmation dialog
  before calling the apply API with `confirm=true` — mirroring the
  backend's requirement that nothing reaches the World Model without an
  explicit confirmation step.

## Known limitations (stated honestly)

- **No search engine.** URLs must be supplied explicitly; the system
  cannot discover new URLs on its own.
- **Claim/conflict extraction is deterministic**, not semantic — it is
  sentence splitting plus lexical similarity, not an LLM-based
  understanding of meaning. This is documented in the `research.py` module
  docstring and reflected in `status()`'s response text.
- **Evidence extraction is sentence-bounded**: very short pages (e.g. a
  single terse sentence) may legitimately produce zero evidence records;
  this is reported honestly as zero, never fabricated.
- **Source quality is a static heuristic**, not a live reputation service —
  it does not (and cannot, in this build) verify publisher authority beyond
  domain-level heuristics.
