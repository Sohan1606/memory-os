# V10.2 implementation status — Evidence-Governed Adaptive Cognitive Policy

Branch `implementation/v10.2`. This document reports the corrective pass that
rebuilt the V10.2 CORE and RUNTIME slices on top of the released engines,
per `docs/V10.2-MASTER-SPEC.md`. Truth before demo polish: everything below
is either implemented and verified by named tests, or explicitly deferred.

## IMPLEMENTED

### CORE — evidence, signals, gate, governance, boundary

1. **Evidence model (`PolicyEvidenceAssembler`, `governance.py`).** Emits only
   canonical records: EventBus `outcome.observed`/`outcome.recorded` records,
   evaluated predictions, structured model-error records, decision outcomes,
   intervention outcomes (verdict from the canonical reaction event or the
   suppression decision — never topic text), autonomy dispositions, and
   learning references by id. Every item carries kind, record id, provenance
   (the emitting canonical service), correlation id, timestamp, epistemic
   state, and user scope. Policy rows and policy/governance events are
   structurally inadmissible (§10.6): `test_policy_rows_are_not_evidence`,
   `test_policy_and_governance_events_are_not_evidence`.
2. **Structured signal derivation (`LearningSignalDeriver`).** Deterministic
   rules over the spec catalog (`REPEATED_FALSE_POSITIVE_INTERVENTION`,
   `REPEATED_SUCCESSFUL_INTERVENTION`, `REPEATED_PREDICTION_FAILURE_OF_CLASS`,
   `REPEATED_SUCCESSFUL_DECISION_PATTERN`, `REPEATED_AUTONOMY_SUCCESS`,
   `REPEATED_AUTONOMY_FAILURE`, `REPEATED_MODEL_ERROR_CLASS` — one signal per
   error class). No model calls, no free-text keyword matching (regression:
   `test_deriver_is_deterministic_not_keyword_based`), writes nothing
   (`test_deriver_creates_no_learning_objects`), epistemic state `INFERRED`,
   explicit `INSUFFICIENT_EVIDENCE` with reasons and thresholds.
3. **Class-B gating (`evaluate_evidence_gate`).** N≥3 independent episodes
   (distinct correlation ids), temporal spread ≥2 distinct days for
   ATTENTION/DECISION/AUTONOMY, freshness window, conflict ratio with both
   sides reported, deterministic counts. Boundaries verified in
   `test_v102_governance_core.py` (1 episode, 2 episodes, 5 episodes in one
   correlation, 3 episodes on one day, stale window, conflict ratio).
4. **Governance state (`PolicyGovernanceService`).** Exact lifecycle
   CANDIDATE→VALIDATING→PROPOSED→ACCEPTED→ACTIVE, and from ACTIVE:
   WEAKENED/DEFERRED/SUPERSEDED/EXPIRED, pre-ACTIVE REJECTED. Append-only
   `policy_governance_history`; every transition requires reason, evidence
   refs and correlation id and emits `governance.transition` with the full
   payload. Illegal transitions raise and change nothing. Validation parks
   insufficient candidates in VALIDATING with the verdict and reason — they
   never reach the user as proposals.
5. **Confirmation boundary.** PROPOSED→ACCEPTED requires an explicit
   confirmation flag AND the existing `AutonomyGovernor` disposition (a
   BLOCKED governor refuses acceptance and changes nothing). Application
   goes through the engine's own `observe()` with
   `origin="v10_2_governed_adaptation"` — distinct from `origin="user"` for
   explicit utterances — so the engine emits its own canonical
   `policy.updated`, honors the finite vocabulary, weak-evidence confidence
   and reversibility. No auto-accept path exists anywhere.
6. **MODEL_HANDLING is governance-only.** `model_handling_strategy` is not a
   released engine dimension and no safe consumer seam exists in the real
   model-routing stack, so candidates may be proposed but activation is
   refused (`test_model_handling_is_governance_only`); the health marker
   reports `model_handling_activatable: false`.
7. **Evidenced-cause rejection and supersession.** Rejecting an applied
   adaptation reverts through the engine's canonical revert path;
   supersession retains the full prior version and history; conflicting
   PROPOSED candidates are resolved at acceptance with cross-references.
8. **Evidence-role separation (§12.1).** Outcome records of turns influenced
   under §11 are measurement evidence, never adaptation evidence for a new
   candidate of the same target (`consulted_turns_by_target`); adaptation
   evidence frozen at acceptance is never re-counted
   (`consumed_evidence_by_target`). Verified end-to-end in
   `test_measurement_harmful_influence_and_weakening` (no evidence recycling
   after weakening).

### RUNTIME — one bounded, correlation-scoped evaluation per turn

9. **`PolicyRuntimeCoordinator`** (V10.1 `MaintenanceRuntimeCoordinator`
   patterns): exactly one top-level evaluation per correlation id, persisted
   and idempotent (replay returns the stored result), terminal correlation
   markers `::reaudit1` and `::pgov1` for both coordinators (governance and
   maintenance are bounded siblings — no recursion), no scheduler, no
   daemon, no subscribers, no process-global state. Hand-emitting every
   V10.2 event type creates zero runs.
10. **Incremental watermark.** The relevance gate records the newest
    evaluated evidence event id; a new governed evaluation runs when ACTIVE
    adaptations exist, an explicit request arrives, or unevaluated outcome
    records exist beyond the watermark. Ordinary turns pay only the gate
    (`NO_GOVERNANCE_NEEDED`, no policy stages, no engine writes).
11. **Real proposal generation, surfaced in the same turn** (PR #14
    visibility): bounded to one candidate per turn, built from real
    assembled evidence, deduplicated against open candidates, and surfaced
    in the turn's trace, chat response and surface lifecycle
    (`WAITING_FOR_POLICY_CONFIRMATION`).
12. **Future-turn influence through real consumers.** ACTIVE adaptations
    are consulted via the released context-bundle consumer seam
    (`context.preferences`): the adapted value enters the response context
    when the engine confidence is high enough, and a
    `governance.consultation` event is recorded only then, naming the
    adaptation, consumer, matched scope and concrete effect. Dropping the
    engine confidence below the threshold removes the consultation
    (`test_consultation_requires_real_consumer_proof`).
13. **Measurement.** ADAPTATION evidence (frozen at acceptance) is reported
    separately from OUTCOME evidence (post-activation observations per
    influenced turn, measured on later turns). Categories:
    SUCCESSFUL_INFLUENCE / NEUTRAL_INFLUENCE / HARMFUL_INFLUENCE /
    INSUFFICIENT_EVIDENCE / CONFLICTING_OUTCOMES; zero observations reports
    "no measured outcomes yet"; no aggregate score exists anywhere.
14. **Deterministic harm handling.** Two HARMFUL_INFLUENCE observations
    (`HARM_WEAKEN_MIN = 2`) deterministically WEAKEN the adaptation and
    revert the engine to its prior value; the weakened adaptation is no
    longer consulted and its evidence cannot be recycled.
15. **Additive API** (existing verified-principal boundary, no new identity
    model): `GET /api/v10/governance/adaptations` (+state/limit),
    `GET .../{id}` (+history), `GET .../{id}/measurements`,
    `POST .../confirm` (requires `confirmation`, 409 on governor block,
    bounded `::pgov1` re-validation mirrored additively from the V10.1
    confirm pattern), `POST .../reject`, `POST .../defer`. Chat responses
    carry a compact `policy_governance` summary.
16. **Portability.** The five governance tables ride the existing
    `memory-os-export` format (domains `user_model`/`events`); restore
    reproduces state, append-only history, frozen evidence refs, provenance,
    epistemic state, derivation rule and scope; validation rejects dangling
    evidence references and reports same-id/different-content conflicts with
    fingerprints; re-import is idempotent.
17. **Surface.** The six V10.2 stages were added to the existing
    conversation-first SurfaceLifecycle vocabulary and are emitted only when
    the corresponding real work ran in that turn.
18. **Persistence regression fixed at the root.** `Database` connections are
    instance-scoped (previously cached in a process-global thread-local keyed
    by `id(self)`, which is not unique across instance lifetimes — a fresh
    Database could inherit a dead instance's connection to a different
    file). This was the root cause of the order-dependent full-suite
    provenance failure; regression:
    `test_database_connections_are_instance_scoped`.

## DEFERRED / NOT IMPLEMENTED (truthful)

1. **MODEL_HANDLING activation** — deliberately governance-only (CORE
   decision 4 above). No fake model-routing capability was added.
2. **REPEATED_PREDICTION_FAILURE_OF_CLASS / REPEATED_SUCCESSFUL_DECISION_PATTERN
   / REPEATED_AUTONOMY_SUCCESS proposals** — the signals are derived and
   reported honestly, but no existing policy dimension is justified by them
   (candidacy `NONE`): inventing a target would be dishonest adaptation.
   `REPEATED_AUTONOMY_FAILURE` derives but the autonomy governor boundary is
   intentionally never relaxed by governance.
3. **Aggregate policy scoring** — intentionally absent (spec §12: no
   aggregate score).
4. **Same-turn measurement of the current turn's consultation** —
   deliberately measured on a later turn; the current turn's outcome records
   may not exist yet, and freezing an early INSUFFICIENT_EVIDENCE verdict
   would be premature.
5. **UI beyond the six stage labels** — CORE before UI; the frontend shows
   the released conversation-first surface with V10.2 stage labels.

## CORE decisions

1. Effective policy stays in `policies` + `CognitivePolicyEngine`; governance
   state is additive (`policy_governance*` tables). Governance never writes
   policy rows directly — only through the engine's own paths.
2. Governed adaptation is a third evidence origin
   (`v10_2_governed_adaptation`) alongside explicit user instruction
   (`user`); V8.2 `apply_utterance()` semantics, vocabulary validation, weak
   accumulation, `MIN_CONFIDENCE_TO_APPLY` and reversibility are unchanged.
3. Policy state is context, never evidence (§10.6); the assembler cannot
   read policy rows as evidence and the deriver cannot see current values
   when deriving candidacy.
4. The confirmation boundary is absolute: initiative/intervention/autonomy/
   model-trust increases require explicit user confirmation plus the
   AutonomyGovernor; the governor cannot be weakened by governance.
5. Runtime bounds are structural (terminal markers, persisted idempotency,
   one top-level evaluation per turn) — not conventions.
6. Evidence-role separation is enforced in code: outcome evidence and
   consumed adaptation evidence are excluded from candidacy re-gating.
7. Governance events (`governance.transition`, `governance.consultation`,
   `governance.observation`) are registered with labels; legacy
   `policy.proposed`/`policy.updated`/`policy.reverted` are untouched.
